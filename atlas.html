读图检查 / MISREAD

三个常见误读

  • ×

    block_table 不是 KV 字节。它只是 CPU 侧的编号；数据在设备 tensor 里。

  • ×

    共享不是复制。A / A′ 是两条引用指向 b9，不是两份 b9 数据。

  • ×

02

层间来源 / KV · INDEX-K · TOP-K

第 24 层，三种来源
来自同一层吗？

不全是。KV 与 index-K 是“读哪一层的已有数据”；Top-k 是“候选位置和选择结果在哪里产生 / 被沿用”。层 24 正好站在分界上：KV 与 index-K 看 20，候选集来自 20，但 Top-k 结果在本层产生。

候选路径 / CANDIDATES

Top-k 的候选只走一条路

L20 全部合法位置 全位置评分 → 候选集
候选集 来自 L20 传递的是位置集合
L24 仅候选内重评 在本层产出 Top-k
L26 不重算评分 沿用 L24 的 Top-k

示意图，不代表实际候选数量或 k 值；只表达“谁产生、谁重评、谁沿用”。

两种共享 / TWO KINDS

不要合成一个“跨层缓存”

index-K 共享 读同一份键表示

后续层读取已经存在的 index-K；共享的是已有数据。

Top-k 共享 沿用候选 / 选择结果

后续层沿用位置集合或选择结果；不是同一份键张量。

层 24 是分界：KV / index-K 仍指向 20；Top-k 在本层产生。层 26 才直接沿用 24 的 Top-k。

COMPACT / 只减 query 维

query 行少了，KV / index-K 存储没少。

把同一组 key 0–11 横着排。COMPACT 的 query 行从 4 开始，但 full KV / index-K 路径仍然保存 0–11；不要把它读成删掉前缀 KV。

COMPACT query 行
01234567891011
full KV / index-K 存储
01234567891011

0–3 在 query 轨上标为“不生成”；在 KV / index-K 轨上仍然存在。两条轨的 12 个位置按同一列对齐。

与 OFF 可能不同

MASK 与 COMPACT 共用同一 SWA 可见域；比较对象是这两种截断模式与 OFF：窗口下界不同的位置，attention 数值可能与 OFF 不同。这里不承诺任意 GPU 执行逐 bit 一致。

少行 ≠ 高 MFU

少算 query 行不自动等于 MFU 上升；本页没有 GPU 实测。

只讲完整 12 位置

源码里早期 chunk 仍有 placeholder 行；不要把 8 行形状推广到所有 chunk。
